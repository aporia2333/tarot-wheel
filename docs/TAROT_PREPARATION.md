# 洗切牌与选牌：R01–R04

## 交互

牌阵列表保留牌数、分页、自定义牌阵和模板，删除推荐模块。问题页的示例问题仍保留。

`/shuffle` 是唯一准备页。洗牌次数支持手动输入或交给塔罗师随机决定；洗完直接接一次魔法切牌，不再显示切牌次数选择或开始按钮。切分位置和合牌顺序均由塔罗师决定；执行期间没有再次开始或跳过入口。切牌完成后自动进入 `/draw`。旧 `/cut` 链接会回到准备页并恢复当前阶段。已经保存的旧切牌计划继续按原次数完成。

抽牌页保留两排各 39 张牌、25° 牌弧和自由摆牌区。鼠标和触屏沿竖直方向拖出至少 48px 决定抽取方向；水平拖动浏览手机上的牌组。点击仅拿起，键盘左右键换牌、上下键抽出、Esc 放回。全部抽齐后进度旁出现“一起翻牌”，点击沿用原保存、同一记录 ID 重试和结果页一起翻牌逻辑。全部重抽清空本次选择与摆放，保留准备好的牌序、基础正逆位。

抽出的牌没有可见标题或牌位说明；自定义牌位名称、含义和抽取顺序仍保存在阅读数据中，在结果与解读中使用。摆牌不会改变抽取顺序或正逆位。

## 操作计划和牌序

`src/lib/preparation.ts` 集中管理次数范围、七种动作、动作时长和操作计划。

每个计划包含操作 ID、动作、执行前牌序、连续牌包、移动时间轴、最终自上而下的牌包顺序以及翻转标记。动画按同一个时间轴移动代表牌包，合牌按照最终顺序从底向顶落下。后台没有动画结束后额外洗牌的步骤。

| 动作 | 对应数据变换 |
| --- | --- |
| 过手 | 顶部连续小牌包依次放入新堆，牌包顺序倒置，包内顺序保留 |
| 交错 | 随机中部拆成两摞，每摞随机分成 1–4 张的小包，轮流交错合拢 |
| 桌面混洗 | 散成单牌，生成混合收集次序，部分单牌旋转 180°，同步反转其基础正逆位 |
| 分叠 | 拆成 4–6 个连续牌包，随机次序合拢 |
| 双叠切牌 | 随机切点，下面牌包放到上面 |
| 三叠切牌 | 两个随机切点，三个牌包随机重组 |
| 自由切牌 | 拆成 4–6 包，错落放置，再随机重组 |

相邻同阶段动作不会重复。每一动作包含全部 78 张且没有重复或遗漏。新的水晶球演出绘制全部实际牌包；无版本旧演出仍最多绘制 12 个代表牌包。所有切牌动作都保留包内次序和基础正逆位。

首次洗牌前固定整副牌的初始方向；洗牌过程中只有计划明确旋转的牌改变方向。准备完成后基础方向冻结：向上抽取为基础方向，向下抽取为相反方向。

## 状态和恢复

Zustand 的 `preparation` 状态依次为 `choose-shuffle → shuffling → choose-cut → cutting → ready`。开始阶段和落牌提交都有原子检查，重复点击和迟到的旧操作 ID 不会重复洗切。只有 `ready` 可抽牌，新会话直接访问抽牌页会回到准备页。

sessionStorage 保留同名存储键，升级为 version 3。当前动作计划在播放前保存。刷新或离开后恢复同一计划，从动作开头重播；已完成操作不会重新执行。既有 v1/v2 会话和已选牌保留原牌序、结果、方向与记录 ID，迁移为可继续的旧会话。

角色偏好单独存在 localStorage 的 `tarot_dealer_character_v1`。更换角色不会修改牌组或重启动作。素材加载失败时用基础分层形象继续；减少动态效果模式用短暂静态落牌代替运动，依然提交同一数据计划。

## 可配置参数

当前手动洗牌次数 1–10，随机洗牌 2–4，切牌自动一次。旧随机切牌 1–3 的参数只用于兼容历史逻辑，产品界面不再调用。保存计划的原始动作时长 3.2–5.2 秒，位于 `PREPARATION_CONFIG`，继续用于旧计划校验。新的水晶球演出时长见 `src/lib/preparationMotion.ts`：洗牌 6.8 秒，逐叠切牌 5.6 秒（保存的上一版魔法切牌为 4.6 秒）；中间轮次缩短 20%，减少动态效果模式为 650ms。演出速度不改保存计划或任何随机决定。角色资源和锚点位于各角色 manifest。
