## 产品规则与文档冲突

用户本次明确确认：**保留自动切牌一次，取消切牌次数选择**。因此文档第 7 节的第二轮次数输入不启用。第一轮仍可自行指定洗牌次数或交给占卜师；洗后牌组保持悬浮，占卜师说出过渡台词，550ms 后自动开始一次真实切牌。洗切始终同屏，正常流程没有跳过按钮。

保留手动洗牌 1–10 次、随机洗牌 2–4 次、既有四种洗牌算法、二叠/三叠/自由切牌组合及正逆位规则。桌面混洗原有的翻转计划继续生效，普通切牌不改变正逆位。随机来源继续采用 `crypto.getRandomValues` 与拒绝采样；生产环境不用固定种子。牌阵之书的 4×2、两页、每页八项未改动，抽牌上下方向和全部重抽规则未改动。

## P0：流程与牌组

- 新增版本 5 的展示轨迹，保留版本 2/3/4 的保存计划恢复及验证。
- 首轮：待机 → 唤醒水晶 → 完整牌堆离桌 → 展开 → 分组交错 → 聚拢悬浮。中间轮直接从当前悬浮姿态继续，不再落桌重抬手。
- 洗后：悬浮过渡台词 → 自动切牌一次。切牌：连续块分开 → 在不同深度交换 → 按真实 `collection` 合并 → 放松双手、归位 → 进入原抽牌页。
- 每张实际牌均有独立的 `data-card-id` 与 React key，所有牌背使用同一皮肤地址；实例数量由当前牌组决定。分组与最终层序直接来自保存的同一份操作计划。
- 操作在播放前计算并保存，完成后通过原有 store 的原子守卫提交一次；中途离开只取消动画，底层未提交计划保留，回来重播本轮。刷新不再采样牌序。
- 失焦隐藏时暂停计时与 RAF，恢复后继续；卸载取消 RAF、可见性监听、眨眼/过渡定时器及角色忙碌状态。播放异常显示“重新播放当前动作”，保留本轮开始牌组，此按钮不跳过业务。
- 修复 React 重排与 SVG 动态层序之间的冲突：重新渲染后重新应用真实牌序的绘制层级。

## P1：角色和视觉

- 复用 `portrait-v2.png` 的完整头颈躯干、`limbs-v1.png` 的上臂、前臂、手背/侧手/掌心/收指姿态；没有重绘五官或替换大图。
- 重新校准四个角色的骨骼长度及不对称休息锚点，手臂自然下垂，减少封闭圆环形袖子。袖口跟随精确腕点，上臂和前臂保持相连。
- 水晶侧主控手先抬起并供能，另一手稍后牵引牌组；背 → 侧 → 掌的现有三帧过渡在同一腕点滚转。主控手保持稳定，引导手在交错和交换时作小幅弧线移动。
- 现有袖子贴图以微小局部倾斜表现下垂，独立眼部遮罩轻移表示注意方向；眨眼与动作分开管理，躯干仅有极小前倾。
- 玻璃内雾纹、高光、柔和亮度、稀疏月白/暖金光点和细光丝跟随动作；接触阴影随悬浮减弱、归位恢复，无新增模糊大滤镜。

### 真实资产能力与美术缺口

已实现的是两个独立关节段、腕部滚转和预绘手势，**不是逐指物理动画，也不是 Live2D/Spine 全身变形**。眼神为现有眼部贴图的局部视觉层，头颈躯干维持完整连贯素材；没有独立眼球、发丝骨骼。

后续若需要更真实的细节，具体可交付素材为：

| 素材 | 建议透明画布 | 锚点/要求 |
|---|---|---|
| 每只手放松、轻张、托举、牵引、收指五姿态 | 单张 320×400 或 5 帧条带 | 同一腕点；袖口颜色、比例及光照一致；猫角色保留爪垫和毛边 |
| 每侧前臂袖子在垂落、中弯、抬腕时的三帧 | 单张 384×512 | 肘点和腕点固定，褶皱随弯曲变化；替换当前轻微局部倾斜 |
| 两眼独立巩膜、虹膜/瞳孔、上下眼睑 | 每眼 256×128 | 与 manifest 的眼中心、间距对齐，可在眼睑内遮罩移动 |
| 前后发丝、耳饰的独立图层 | 沿用角色 1254×1254 母图 | 保留头部锚点和现有五官；只作低振幅随动 |

这些素材不阻断当前 P0–P2；本次未安装新依赖、生成新位图或更改现有原始图像。

## P2：扩展和调试

- 三种可复现的轨迹：双组交错、三路穿插、反向弧线；轨迹变体按既有动作语义选择，真实洗牌算法与翻转计划未更换。
- 二叠、三叠及自由切牌沿用连续区块和真实收牌顺序。用户的“一次切牌”指一次操作计划，不等于只切成两段。
- 每角色 `ritual` 配置映射主控手、动作幅度、休息锚点和袖子下垂参数；替换皮肤不改业务 store。
- 动画时间、浮空高度、扇面宽度、投影厚度、光点数量和简化时长集中于 `RITUAL_CONFIG`。固定计划的秩序与深度预编译并由 WeakMap 缓存。
- 桌面使用 8 光点、手机 3 光点、低性能/减少动作 0 光点；慢帧检测进一步关闭环境装饰。减少动作每轮 650ms，仍逐次执行及提交业务。
- 开发环境 `/design-preview?view=motion&debug=1` 提供 seed、动作、拖动/精确进度及状态读数；使用隔离的纯随机源重现动作，不写阅读 store。生产构建和普通预览不显示调试面板。
- 普通预览现在以真实的上一轮结果进行下一轮洗切，洗后悬浮等待“播放切牌”；切后再演示需先洗牌，保证阶段连续。
